# Day23 多文件构建与GDB练习

这是刻意保留i <= count错误的教学工程。先编译，再用条件断点在非法读取前停止；不要求直接运行错误版本或猜其输出。

## 在WSL运行

```bash
cd /mnt/d/43131/c-data-structure-git/linux/day23_build_debug

gdb ./build/app
```

## GDB操作

以下命令在(gdb)提示符后输入：

```gdb
break calculate_sum
run
print count
bt
list
break stats.cpp:9 if i == count
continue
print i
print count
print sum
bt
```

前提：文件保持原有行号，第9行是sum += values[i];。如果自行增加行，请先用list核对行号。条件断点设在循环体内，使i处于作用域中。

预期断点处i=3、count=3、sum=60；下一步读取values[3]将越界。此时不要执行next或continue，使用kill结束被调试进程，出现确认时输入y，再quit退出GDB。

## 修复与验证

将stats.cpp中的i <= count修改为i < count，保存并运行：

```bash
make
./build/app
make
```

预期sum=60和Day23 sum check passed.；第一次make只需重编译stats.cpp并重新链接；紧接着第二次make通常无需构建。

## 头文件依赖验证

```bash
touch stats.h
make -n
make
```

-n显示计划命令而不执行本工程中的配方。应看到main.cpp和stats.cpp都需要重编译，然后重新链接。touch只更新时间；由于依赖时间变化，即使文件内容没改也可触发构建。

## 必须理解

1. stats.h声明接口；stats.cpp提供实现；main.cpp调用接口；Makefile描述依赖与构建命令。
2. 两个目标文件都依赖stats.h，修改头文件会影响两者。
3. make不是编译器；配方中的g++才是编译器驱动。
4. Makefile配方行以真正Tab开头，压缩包已保留Tab。
5. -g生成调试信息，-O0中的O是大写字母，0是数字。
6. build中的Linux产物不提交Git。clean配方仅删除当前工程内的build目录。
