## 二、代码题1：二分查找第一次出现位置

### 1. 题目要求

在有序数组中查找目标值第一次出现的位置。

例如：

```c
int arr[] = {1, 2, 2, 2, 4, 7};
```

查找`2`时应返回下标`1`，而不是任意一个`2`的位置。

### 2. 核心思路

采用闭区间：

```text
[left, right]
```

每轮比较：

- `arr[middle] < target`：搜索右半区
- `arr[middle] > target`：搜索左半区
- `arr[middle] == target`：记录当前位置，继续向左搜索

关键代码：

```c
int middle = left + (right - left) / 2;
```

这种写法比：

```c
(left + right) / 2
```

更能避免整数溢出。

找到目标后不能立即返回，因为左侧可能还有相同元素：

```c
result = middle;
right = middle - 1;
```

### 3. 复杂度

```text
时间复杂度：O(log n)
空间复杂度：O(1)
```

### 4. 面试回答

> 普通二分查找到目标后可以直接返回；如果要求第一次出现的位置，就先保存当前下标，再继续搜索左半区，直到搜索区间为空。

## 三、代码题2：通信数据帧校验

### 1. 数据帧格式

```text
帧头 | LEN | PAYLOAD | CHECKSUM | 帧尾
0xAA | 1B  | LEN字节 |    1B    | 0x55
```

数组下标关系：

| 内容 | 下标 |
|---|---:|
| 帧头 | `0` |
| LEN | `1` |
| 载荷开始 | `2` |
| 校验字节 | `LEN + 2` |
| 帧尾 | `LEN + 3` |
| 整帧长度 | `LEN + 4` |

载荷长度范围：

```text
0～32字节
```

### 2. 正确检查顺序

```text
检查输入指针
→ 检查最小长度
→ 检查帧头
→ 读取并检查LEN
→ 检查总长度
→ 检查帧尾
→ 计算异或校验
→ 比较校验字节
→ 写入输出参数
```

必须先检查长度，再根据LEN访问数组，防止越界读取。

### 3. 异或校验

校验值从LEN开始计算：

```c
uint8_t checksum = len;

for (size_t i = 0; i < len; i++)
{
    checksum ^= buf[2U + i];
}
```

然后与帧中的校验字节比较：

```c
if (checksum != buf[len + 2U])
{
    return false;
}
```

### 4. 输出参数处理

只有全部校验成功后才能修改输出参数：

```c
*payload_len = len;
return true;
```

不能在函数开头执行：

```c
*payload_len = 0;
```

否则校验失败时也会修改调用者的数据。

### 5. 面试回答

> 数据帧解析时要先验证最小长度，再读取长度字段，然后验证总长度、帧头、帧尾和校验值。输出参数采用成功后提交的方式，保证失败时调用者原数据不被修改。

## 四、结构体内存对齐

### 1. 基本规则

- 每个成员的起始地址必须满足自身对齐要求。
- 结构体总大小必须是最大对齐值的整数倍。
- 成员结束后还可能存在尾部填充。

例如：

```c
struct Test
{
    uint16_t a;
    uint8_t  b;
    uint32_t c;
    uint8_t  d;
};
```

成员偏移：

| 成员 | 偏移 |
|---|---:|
| `a` | 0 |
| `b` | 2 |
| `c` | 4 |
| `d` | 8 |

`d`结束后占用9字节，最后补齐到4的整数倍：

```c
sizeof(struct Test) == 12
```

### 2. 优化方式

通常把对齐要求较大的成员放在前面，可以减少中间填充，但可能影响协议格式和硬件寄存器映射，不能随意重排。

### 3. 面试回答

> 结构体成员分别按照自身对齐要求排列，结构体总大小再按照最大成员的对齐值补齐。调整成员顺序可以减少填充，但协议结构体不能只为了节省空间随意修改。

## 五、UART时间计算

8N1表示：

```text
1位起始位 + 8位数据位 + 0位校验位 + 1位停止位
```

因此每发送1字节需要传输10bit。

公式：

```text
发送时间 = 字节数 × 10 ÷ 波特率
```

例1：

```text
288 × 10 ÷ 115200
= 0.025s
= 25ms
```

例2：

```text
144 × 10 ÷ 57600
= 0.025s
= 25ms
```

注意：

```text
秒转毫秒需要乘1000
```

DMA可以减少CPU搬运数据的开销，但不能改变相同波特率下的物理线路传输速度。

## 六、定时器与PWM计算

常用公式：

```text
计数频率 = 定时器输入时钟 ÷ (PSC + 1)

更新频率 = 计数频率 ÷ (ARR + 1)

更新周期 = (ARR + 1) ÷ 计数频率

PWM占空比 = CCR ÷ (ARR + 1)
```

例：

```text
输入时钟：48MHz
PSC = 47
ARR = 1999
CCR = 500
```

计算结果：

```text
计数频率 = 48MHz ÷ 48 = 1MHz

更新频率 = 1MHz ÷ 2000 = 500Hz

更新周期 = 1 ÷ 500Hz = 2ms

占空比 = 500 ÷ 2000 = 25%
```

易错点：

- 频率单位是Hz，周期单位是秒或毫秒。
- 频率和周期互为倒数。
- `PSC`和`ARR`参与计算时通常需要加1。
- 本题占空比中的`CCR`不加1。

## 七、Flash容量与跨页写入

W25Q64容量：

```text
64Mbit ÷ 8 = 8MByte
8 × 1024 × 1024 = 8,388,608 Byte
```

若页大小为256字节，从地址`0x01F8`写入40字节：

```text
页内偏移：0xF8 = 248
当前页剩余：256 - 248 = 8字节
```

因此需要拆分为：

```text
第一次写8字节
第二次写32字节
```

若扇区大小为4KB，地址`0x2345`所在扇区首地址：

```c
0x2345U & ~0xFFFU
```

结果：

```text
0x2000
```

## 八、FreeRTOS队列

FreeRTOS队列默认复制数据，而不是只保存发送变量的地址。

```c
xQueueSend(q, &value, 0);
```

最后一个参数`0`表示：

> 队列满时立即返回失败，不等待可用空间。

常见中断接口：

```c
xQueueSendFromISR();
xTaskNotifyFromISR();
```

ISR中不能调用可能阻塞等待的普通任务接口。

## 九、volatile、原子性与ISR

```c
volatile int count;
```

`volatile`只能保证每次从内存读取或写入，防止编译器省略相关访问，但不能保证：

```c
count++;
```

是原子操作。

`count++`通常包含：

```text
读取 → 修改 → 写回
```

如果ISR和任务共同访问，需要使用：

- 适合中断环境的临界区
- 原子操作
- ISR发送通知，由任务独占修改

不能在ISR中阻塞等待普通互斥锁。

面试回答：

> volatile解决的是编译器优化和可见性问题，不保证复合操作原子性。ISR与任务共享数据时需要临界区、原子操作或消息通知。

```c
HAL_UART_Receive_IT(&huart1, rx_buf, 8);
```

表示启动一次接收8字节的中断请求。

接收完成后需要：

- 在回调中重新启动下一次接收

- 检查溢出等UART错误

- 防止接收缓冲区被下一帧覆盖

- DMA循环接收
- UART空闲线检测
- 环形缓冲区

## 十一、TCP Socket API

TCP服务端基本流程：

```text
socket → bind → listen → accept → recv/send → close
```

### 1. accept()

```c
int client_fd = accept(listen_fd, NULL, NULL);
```

如果返回7：

> 7是新连接的文件描述符，用于与该客户端通信。

原来的`listen_fd`仍用于接受其他客户端。

### 2. recv()

| 返回值 | 含义 |
|---|---|
| `n > 0` | 本次实际接收到的字节数 |
| `n == 0` | 对端有序关闭发送方向 |
| `n == -1` | 发生错误，需要检查`errno` |

TCP是字节流协议，没有天然消息边界，需要通过：

- 固定长度
- 分隔符
- 长度字段

解决粘包和拆包问题。

## 十二、C++资源管理

如果类直接管理文件句柄，默认复制可能导致两个对象同时保存相同句柄，最终发生重复关闭。

需要禁止复制：

```cpp
LogFile(const LogFile &) = delete;
LogFile &operator=(const LogFile &) = delete;
```

允许移动：

```cpp
LogFile(LogFile &&other) noexcept;
LogFile &operator=(LogFile &&other) noexcept;
```

移动操作需要：

- 转移资源所有权
- 将源对象置为空状态
- 移动赋值前释放目标对象原资源
- 保证析构空对象是安全的

面试回答：

> 对于独占文件句柄，应禁止复制并实现移动语义。移动时只转移所有权，不复制底层资源。

## 十三、GCC、Makefile与GDB

### 1. GCC编译命令

```bash
gcc -std=c11 -g -Wall -Wextra main.c sensor.c -o app
```

参数含义：

| 参数 | 作用 |
|---|---|
| `-std=c11` | 使用C11标准 |
| `-g` | 生成调试信息 |
| `-Wall` | 开启常用警告 |
| `-Wextra` | 开启额外警告 |
| `-o app` | 指定输出文件名 |

`undefined reference`属于链接阶段错误，优先检查：

- 定义所在源文件是否参与链接
- 声明和定义名称是否一致
- 函数是否被`static`限制在其他源文件中

### 2. Makefile基本格式

```makefile
目标: 依赖
	命令
```

命令行开头默认使用真实Tab，不能使用普通空格代替。

### 3. GDB常用命令

```gdb
bt
info locals
info threads
```

分别用于查看：

- `bt`：函数调用栈
- `info locals`：当前栈帧的局部变量
- `info threads`：线程列表
