# Day20：数据结构与算法复习

## 一、单链表

### 1. 单链表特点

单链表节点通常包含数据和后继指针：

```c
typedef struct ListNode
{
    int value;
    struct ListNode *next;
} ListNode;
```

特点：

- 节点可以分散存储。
- 通过`next`访问后继节点。
- 访问第`k`个节点需要从头遍历。
- 随机访问最坏时间复杂度为`O(n)`。
- 已知插入位置时，修改指针可以达到`O(1)`。
- 动态节点删除后需要正确释放，避免内存泄漏。

### 2. 合并两个有序链表

核心思路：

1. 建立哑节点`dummy`。
2. 使用`tail`指向结果链表尾部。
3. 比较两个链表的当前节点。
4. 将较小节点接到`tail`之后。
5. 对应链表通过`list = list->next`向后移动。
6. 一条链表结束后，直接接上另一条剩余部分。
7. 返回`dummy.next`。

不能写：

```c
list1++;
```

链表节点不保证连续存储，必须写：

```c
list1 = list1->next;
```

复杂度：

```text
时间复杂度：O(m+n)
额外空间复杂度：O(1)
```

这里复用了原链表节点，没有申请新节点。

### 3. 哑节点的作用

哑节点可以统一处理结果链表的第一个节点，减少“头节点单独处理”的特殊分支。

```c
ListNode dummy = {0, NULL};
ListNode *tail = &dummy;
```

最后：

```c
return dummy.next;
```

返回`dummy.next`是安全的，因为它保存的是原链表节点地址，不是局部变量`dummy`的地址。

### 4. 必测边界

- 两个链表都为空。
- `list1`为空。
- `list2`为空。
- 两边当前值相等。
- 两个链表长度不同。
- 一条链表提前结束。
- 合并后最后一个节点的`next`为`NULL`。

## 二、环形队列

### 1. 数据结构

```c
#define QUEUE_CAPACITY 5U

typedef struct
{
    int data[QUEUE_CAPACITY];
    size_t head;
    size_t tail;
    size_t count;
} RingQueue;
```

含义：

- `head`：下一个读取位置。
- `tail`：下一个写入位置。
- `count`：当前有效元素数量。

### 2. 队空和队满

因为额外维护了`count`，可以使用全部存储槽位：

```c
队空：count == 0U
队满：count == QUEUE_CAPACITY
```

`head == tail`本身不能区分队空与队满：

```text
head == tail，count == 0：队空
head == tail，count == capacity：队满
```

### 3. 入队

```c
queue->data[queue->tail] = value;

queue->tail =
    (queue->tail + 1U) % QUEUE_CAPACITY;

++queue->count;
```

操作前必须检查：

- `queue`是否为`NULL`。
- 队列是否已满。

队满时入队失败，并保持原状态不变。

### 4. 出队

```c
*value = queue->data[queue->head];

queue->head =
    (queue->head + 1U) % QUEUE_CAPACITY;

--queue->count;
```

操作前必须检查：

- `queue`是否为`NULL`。
- `value`是否为`NULL`。
- 队列是否为空。

### 5. 查看队头

`peek()`读取`data[head]`，但不能修改：

- `head`。
- `tail`。
- `count`。

### 6. 回绕

不能只写：

```c
++queue->tail;
```

否则下标走到数组末尾后会越界。

应使用：

```c
queue->tail =
    (queue->tail + 1U) % QUEUE_CAPACITY;
```

### 7. 复杂度

```text
push：O(1)
pop：O(1)
peek：O(1)
固定数组存储：O(N)
每次操作额外空间：O(1)
```

## 三、二分查找

二分查找要求数据按照比较规则有序。

安全的中点计算：

```c
mid = left + (right - left) / 2U;
```

相较于：

```c
mid = (left + right) / 2U;
```

前一种写法可以降低`left + right`溢出的风险。

使用闭区间`[left, right]`时，通常采用：

```c
while (left <= right)
```

查找第一个等于目标值的位置时，遇到目标不能立即返回，还要继续向左侧搜索。

## 四、有序数组原地去重

有序数组可以使用快慢指针：

- `fast`扫描所有元素。
- `slow`指向当前有效结果末尾。
- 遇到不同元素时移动`slow`并写入。

复杂度：

```text
时间复杂度：O(n)
额外空间复杂度：O(1)
```

只比较相邻元素的方法依赖数组有序，不能直接用于任意无序数组。

输入长度为0时必须单独处理，不能直接返回`slow + 1`。

## 五、UART环形缓冲区项目映射

如果将环形缓冲区用于STM32串口接收：

```text
生产者：UART中断或接收回调
消费者：协议解析任务
```

生产者：

```text
字节写入data[tail]
→ tail回绕
```

消费者：

```text
读取data[head]
→ head回绕
```

UART字节流发生溢出时，不能静默覆盖未解析数据，否则可能破坏协议帧边界。

推荐处理：

```text
记录overflow
→ 丢弃异常帧
→ 重置解析状态
→ 重新寻找下一帧头
```

## 六、volatile与并发安全

`volatile`不能保证：

- 原子性。
- 互斥。
- 操作顺序。
- 多线程或中断并发安全。

今天实现的`count`版本中：

```c
生产者执行：++count
消费者执行：--count
```

双方都修改`count`，存在读—改—写竞态。

工程中可采用：

- 临界区。
- 原子变量。
- 单生产者单消费者结构。
- FreeRTOS `StreamBuffer`。
- FreeRTOS `Queue`及其`FromISR`接口。

## 七、环形数组和链表的选择

UART接收更适合固定数组环形缓冲区，因为：

- 入队和出队都是确定的`O(1)`。
- 不需要在中断中调用`malloc/free`。
- 不会产生动态内存碎片。
- 不存在每个节点的指针开销。
- 连续存储具有更好的缓存局部性。
- 最大内存占用固定。
- 队满策略和高水位可以明确监控。

链表可能存在：

- 分配时间不确定。
- `malloc()`失败。
- 内存泄漏。
- 野指针或悬空指针。
- 内存碎片。
- 容量无限增长后耗尽内存。

## 八、115200 8N1缓冲区计算

8N1传输一个有效数据字节需要：

```text
1位起始位 + 8位数据位 + 1位停止位 = 10位
```

理论字节速率：

```text
115200 ÷ 10 = 11520字节/秒
```

解析任务阻塞20ms时：

```text
11520 × 20 ÷ 1000 = 230.4字节
```

最坏情况需要至少231字节。

128字节缓冲区只能支撑：

```text
128 ÷ 11520 ≈ 11.1ms
```

因此不足以覆盖20ms阻塞。

工程上可选择：

```text
最低：256字节
留有更大余量：512字节
```

最终容量应结合实际RAM和最大阻塞时间确定。

需要监控：

- 当前队列深度。
- 历史最高水位。
- 溢出次数。
- 丢弃字节或帧数量。
- 最大解析延迟。
- 重新寻找帧头的次数。

## 九、Day20错题

1. 单链表访问第`k`个节点不是`O(1)`，最坏为`O(n)`。
2. 使用全部环形槽位时，只靠`head == tail`无法区分空和满。
3. 合并有序链表不是`O(n²)`，而是`O(m+n)`。
4. 复用原节点的迭代合并额外空间为`O(1)`。
5. 链表不能使用`list++`，必须使用`list = list->next`。
6. 测试函数必须真正调用目标函数并包含断言。
7. `tail++`不能实现环形回绕，应使用取模。
8. 环形队列接口必须检查队列指针和输出指针。
9. `head < tail`不是环形队列始终成立的条件。
10. `count = tail - head + 1`不能处理下标回绕。
11. `volatile`不能单独保证中断和任务并发安全。
12. `11520`的单位是字节/秒，不是bit。
13. 20ms积累量需要同时进行毫秒换算和10bit/Byte换算。
